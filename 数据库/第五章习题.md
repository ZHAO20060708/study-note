## 5.2

请编写一个使用 JDBC 元数据特性的 Java 方法，该方法用 ResultSet 作为输入参数，并把结果输出为采用合适的名称作为列标题的表格形式。

``` java
import java.sql.*;

/**
 * 使用 JDBC 元数据将 ResultSet 输出为对齐的表格形式。
 */
public class ResultSetPrinter {

    /**
     * 将 ResultSet 的内容打印为控制台表格，列标题来自 ResultSetMetaData。
     *
     * @param rs 要打印的 ResultSet（调用前 rs 应指向第一行之前的位置）
     * @throws SQLException 如果访问结果集元数据或数据时发生数据库错误
     */
    public static void printResultSetAsTable(ResultSet rs) throws SQLException {
        ResultSetMetaData metaData = rs.getMetaData();
        int columnCount = metaData.getColumnCount();

        // 1. 收集列标题（优先使用列标签，别名友好）
        String[] headers = new String[columnCount];
        for (int i = 1; i <= columnCount; i++) {
            // getColumnLabel() 返回用于显示的列标题，如果使用了 AS 别名，则返回别名；
            // 若未指定别名，通常等同于 getColumnName()。
            headers[i - 1] = metaData.getColumnLabel(i);
        }

        // 2. 先遍历一次数据，确定每列的最大宽度（至少与列标题等宽）
        //    注意：这会消耗 ResultSet，如果需要多次读取，可先存入集合。
        int[] columnWidths = new int[columnCount];
        for (int i = 0; i < columnCount; i++) {
            columnWidths[i] = headers[i].length();
        }

        // 将数据暂存到二维字符串列表，同时更新列宽
        java.util.List<String[]> rows = new java.util.ArrayList<>();
        while (rs.next()) {
            String[] row = new String[columnCount];
            for (int i = 1; i <= columnCount; i++) {
                String value = rs.getString(i);
                // 处理 null 值，显示为 "NULL"
                if (value == null) {
                    value = "NULL";
                }
                row[i - 1] = value;
                // 更新最大宽度
                if (value.length() > columnWidths[i - 1]) {
                    columnWidths[i - 1] = value.length();
                }
            }
            rows.add(row);
        }

        // 3. 构建分隔线
        StringBuilder separator = new StringBuilder("+");
        for (int width : columnWidths) {
            separator.append("-".repeat(width + 2)); // 左右各一个空格
            separator.append("+");
        }
        String separatorLine = separator.toString();

        // 4. 输出表格
        System.out.println(separatorLine);

        // 输出表头
        System.out.print("|");
        for (int i = 0; i < columnCount; i++) {
            System.out.printf(" %-" + columnWidths[i] + "s |", headers[i]);
        }
        System.out.println();

        System.out.println(separatorLine);

        // 输出数据行
        for (String[] row : rows) {
            System.out.print("|");
            for (int i = 0; i < columnCount; i++) {
                System.out.printf(" %-" + columnWidths[i] + "s |", row[i]);
            }
            System.out.println();
        }

        System.out.println(separatorLine);
    }

    // 可选：用于快速测试的 main 方法（需要数据库驱动及连接信息）
    public static void main(String[] args) {
        // 示例用法（假设已有连接和查询）

        } catch (SQLException e) {

}
```

## 5.3

假设我们希望找到在某门给定课程之前必须选修的所有课程。这意味着不仅要找到该课程的先修课程，还要找到先修课程的先修课程，如此等等。请使用 JDBC 来编写一段完整的 Java 程序，它能够：

- 从键盘获得 course_id 的值。
- 使用通过 JDBC 提交的 SQL 查询来查找该课程的先修课程。
- 对于返回的每门课程，找到它的先修课程，并反复执行此过程，直到没有找到新的先修课程为止。
- 打印结果。

对于本题不要使用递归的 SQL 查询，而是使用前面描述的迭代方法。在一所大学意外地创建了一个先修课程环路（也就是说，比如，A 课程是 B 课程的先修课程，B 课程是 C 课程的先修课程，且 C 课程是 A 课程的先修课程）的情况下，一个完善的解决方案对于这样的错误情况应该是稳健的。

### 假设条件

在编写代码之前，假设数据库中有一张标准的先修课程表 `prereq`，其结构如下：

- `course_id` (VARCHAR): 课程编号
- `prereq_id` (VARCHAR): 该课程的先修课程编号

### Java 完整程序

请确保在运行此代码前，已经将相应数据库的 JDBC 驱动（例如 MySQL 的 `mysql-connector-java.jar`）添加到了项目的 classpath 中。

```java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.HashSet;
import java.util.LinkedList;
import java.util.Queue;
import java.util.Scanner;
import java.util.Set;

public class PrerequisiteFinder {

    // 数据库连接配置 (请根据实际情况修改)
    private static final String DB_URL = "jdbc:mysql://localhost:3306/university_db";
    private static final String DB_USER = "root";
    private static final String DB_PASSWORD = "password";

    public static void main(String[] args) {
        // 1. 从键盘获取 course_id
        Scanner scanner = new Scanner(System.in);
        System.out.print("请输入需要查询的课程编号 (course_id): ");
        String initialCourseId = scanner.nextLine().trim();
        scanner.close();

        if (initialCourseId.isEmpty()) {
            System.out.println("课程编号不能为空！");
            return;
        }

        // 用于保存最终所有的先修课程结果
        Set<String> allPrerequisites = new HashSet<>();
        
        // 用于防止循环依赖（记录已经作为查询条件执行过的课程）
        Set<String> visitedCourses = new HashSet<>();
        
        // 待查询先修课的队列 (用于迭代)
        Queue<String> coursesToProcess = new LinkedList<>();

        // 初始化：将用户输入的课程加入队列，并标记为已访问（防止如果有环路绕回这门课时发生死循环）
        coursesToProcess.add(initialCourseId);
        visitedCourses.add(initialCourseId);

        // SQL 查询语句：只查询直接先修课
        String sql = "SELECT prereq_id FROM prereq WHERE course_id = ?";

        // 2. 使用 JDBC 连接数据库并迭代查询
        try (Connection conn = DriverManager.getConnection(DB_URL, DB_USER, DB_PASSWORD);
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            System.out.println("正在查询数据库，请稍候...");

            // 只要队列中还有需要查询的课程，就继续循环
            while (!coursesToProcess.isEmpty()) {
                // 取出队首的课程
                String currentCourseId = coursesToProcess.poll();
                
                // 设置 SQL 参数
                pstmt.setString(1, currentCourseId);

                // 执行查询
                try (ResultSet rs = pstmt.executeQuery()) {
                    while (rs.next()) {
                        String prereqId = rs.getString("prereq_id");
                        
                        if (prereqId != null && !prereqId.trim().isEmpty()) {
                            // 将找到的先修课程加入最终结果集
                            allPrerequisites.add(prereqId);

                            // 【防死循环的核心逻辑】
                            // 如果这门先修课程之前没有被当作查询条件处理过
                            if (!visitedCourses.contains(prereqId)) {
                                visitedCourses.add(prereqId);       // 标记为已访问
                                coursesToProcess.add(prereqId);     // 加入队列，以便后续查询它的先修课
                            }
                        }
                    }
                }
            }

            // 3. 打印结果
            System.out.println("\n课程 [" + initialCourseId + "] 的所有先修课程如下:");
            if (allPrerequisites.isEmpty()) {
                System.out.println("(无先修课程)");
            } else {
                for (String prereq : allPrerequisites) {
                    System.out.println("- " + prereq);
                }
                System.out.println("总计: " + allPrerequisites.size() + " 门课程。");
            }

        } catch (SQLException e) {
            System.err.println("数据库访问出错!");
            e.printStackTrace();
        }
    }
}
```

## 5.4

请描述你会选择使用嵌入式 SQL 而不是单独使用 SQL 或仅仅使用通用程序设计语言的情况。

当你需要在一个应用程序中，将 SQL 强大的集合操作能力与过程化语言精细的控制流深度融合，同时又对性能、安全性和编译时检查有严格需求时，我就会选择使用嵌入式 SQL。它可以恰好弥补“单独使用 SQL”和“仅仅使用通用程序设计语言”各自的不足。

### 选择嵌入式 SQL 的典型情况

具体有以下几类场景：

#### 场景一：高性能、高并发的核心交易系统

例如，在 C 语言编写的金融核心账务系统中，需要遍历数百万账户进行日终计息。逻辑是：

1. 声明一个游标，查询某类账户；
2. 逐行取出，根据账户属性用 C 函数计算利息（涉及外部利率库、复杂分段计息公式）；
3. 立即嵌入 `UPDATE` 语句更新余额并写入交易流水；
4. 所有操作在同一数据库连接和事务内完成。

这里，嵌入式 SQL 让游标循环和计算零缝隙衔接，每次更新都使用预编译好的静态 SQL，几乎没有性能浪费。如果用纯 SQL 存储过程，很难调用外部 C 利率库；如果用通用语言自己管理数据文件，查询和事务根本跟不上。

#### 场景二：编译期就要求绝对安全和类型匹配的系统

在航空或医疗设备控制软件中，不允许 SQL 语句在运行时才暴露出语法错误或类型不匹配。嵌入式 SQL 的预编译器会在构建时就检查：

- 表、列是否存在；
- 宿主变量类型与列类型是否兼容；
- 用户的增删改查权限。

这比动态拼接 SQL（错一个引号可能到半夜上线才发现）可靠得多。同时，宿主变量直接绑定，避免了运行时解析，也根除了 SQL 注入。

#### 场景三：与遗留大型系统整合

许多银行、保险的核心系统使用 COBOL 或 PL/I 编写，业务逻辑已固化。如果要扩展新功能，最佳方式是继续在现有代码中嵌入 SQL 访问 DB2 或 Oracle 数据库，而不是用新语言重写。这种场景下，嵌入式 SQL 是唯一既能保持原有资产又能利用数据库能力的务实选择。

#### 场景四：资源受限或特殊环境

在嵌入式设备（如路由器、工业控制器）中，系统可能使用 SQLite 并提供 C API，但直接使用那些 API 要手工控制绑参、提取数据，代码冗长。如果用 SQLite 的嵌入式 SQL 变体，或通过预编译器把 SQL 转成 C 调用，代码可读性大增，且仍然保持 C 语言的高效和硬件接近性。这比外挂一个脚本语言解释器去单独执行 SQL 更省资源，也更可控。
